Лабораторная работа 5
Шардирование PostgreSQL: Router и Consistent Hashing
Цель работы
Научиться распределять данные собственного backend-сервиса между несколькими
экземплярами PostgreSQL и понять, как выбор стратегии шардирования влияет на
перенос данных при изменении количества шардов.
В работе необходимо сравнить два подхода:
• hash(key) % N;
• Consistent Hashing с использованием hash ring.
Важно
Работа выполняется только в рамках собственного backend-сервиса.
Не нужно создавать отдельный учебный проект с искусственными users или orders.
Используйте сущность, таблицу и данные своего сервиса.
1. Выбор данных для шардирования
Выберите одну сущность своего сервиса, которую будем распределять между шардами.
Примеры:
• пользователи;
• заказы;
• организации;
• документы;
• сообщения;
• товары;
• платежи.
Определите shard key — поле, по которому будет определяться расположение записи.
Например:
user_id
tenant_id
organization_id
Необходимо объяснить
1. Какую сущность вы выбрали?
2. Какое поле используется как shard key?
3. Почему выбран именно этот ключ?
4. Насколько равномерно, на ваш взгляд, он будет распределять данные?
5. Какие запросы вашего сервиса используют этот ключ?
2. Запуск нескольких PostgreSQL
Запустите минимум три экземпляра PostgreSQL:
PostgreSQL 0
PostgreSQL 1
PostgreSQL 2
Рекомендуется использовать Docker Compose.
Все экземпляры должны быть доступны вашему backend-сервису.
Цель этого этапа — получить несколько независимых PostgreSQL, между которыми
можно распределять данные.
3. Реализация простого Router
Реализуйте в своём сервисе простой механизм определения shard.
На первом этапе используйте стратегию:
shard = hash(shard_key) % N
где N — количество шардов.
Например:
hash(101) % 3 → Shard 2
hash(102) % 3 → Shard 0
hash(103) % 3 → Shard 1
Router должен определить, к какому экземпляру PostgreSQL необходимо обратиться для
работы с конкретной записью.
4. Распределение данных
Загрузите в свой сервис некоторое количество данных выбранной сущности.
Количество данных должно быть достаточным, чтобы увидеть распределение между
шардами.
Например:
100 000 записей
После загрузки покажите:
Shard 0 → N записей
Shard 1 → N записей
Shard 2 → N записей
Сделайте вывод:
• насколько равномерно распределились данные;
• есть ли заметный дисбаланс;
• может ли такой дисбаланс стать проблемой.
5. Что произойдёт при добавлении нового shard?
Теперь представьте, что к системе добавляется ещё один экземпляр:
3 shards → 4 shards
Раньше использовалось:
hash(key) % 3
Теперь:
hash(key) % 4
Для набора данных из предыдущего задания определите, сколько записей изменят свой
shard.
Например:
Всего записей: 100 000
Новый shard: Shard 3
Изменили shard: 74 321
Не изменили: 25 679
Процент перемещаемых данных необходимо посчитать самостоятельно.
Сделайте вывод
Почему добавление одного PostgreSQL может привести к необходимости перемещения
большого количества данных?
6. Реализация Consistent Hashing
Теперь реализуйте упрощённый Consistent Hash Ring.
Общий принцип:
hash(shard_key)
 ↓
точка на hash ring
 ↓
ближайший shard по кольцу
Для начала достаточно реализовать базовую версию без сложных оптимизаций.
7. Сравнение стратегий
Повторите эксперимент из задания 5:
3 shards → 4 shards
Но теперь используйте Consistent Hashing.
Сравните количество перемещаемых записей.
Результат представьте примерно в таком виде:
 Перемещено
hash(key) % N XX %
Consistent Hashing YY %
Объясните
1. Почему результаты отличаются?
2. Почему Consistent Hashing позволяет уменьшить объём перемещаемых данных?
3. Что произойдёт, если добавить ещё один shard?
4. Что произойдёт, если удалить shard?
8. Итог
В конце работы сформулируйте вывод на 5–10 предложений:
• что такое shard;
• что такое shard key;
• зачем нужен router;
• как работает hash(key) % N;
• какая проблема возникает при изменении N;
• как Consistent Hashing решает эту проблему;
• какой подход вы бы выбрали для своего сервиса и почему.

4. Как работает hash(key) % N?
5. Почему изменение количества shard’ов является проблемой?
6. Что такое Consistent Hash Ring?
7. Почему при добавлении shard’а не приходится переносить все данные?
8. Что такое virtual nodes и зачем они нужны?
