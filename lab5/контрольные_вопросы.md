# Контрольные вопросы — лабораторная №5

## 1. Что такое shard?
Независимая БД с частью строк логической сущности. У нас три PostgreSQL с readings.

## 2. Что такое shard key?
Поле для выбора узла: user_id. Оно известно до записи и объединяет историю пользователя.

## 3. Почему не распределять случайно?
Без каталога расположения невозможно адресно повторить чтение/обновление.
Детерминированный роутер одинаково вычисляет узел при записи и чтении.
Случайное размещение возможно с каталогом, но требует его согласованного сопровождения.

## 4. Как работает hash(key) % N?
Стабильный хеш ключа делится на число шардов; остаток выбирает узел.
При N=3 user 1 → shard 1, user 2 → shard 2.

## 5. Почему изменение числа шардов — проблема?
Меняется делитель и адреса строк. На нашем наборе 3→4 меняет узел у 100000 из 100000 строк.
Для большого множества равномерных ключей ожидание около 75%, но не гарантия.

## 6. Что такое Consistent Hash Ring?
Упорядоченные точки узлов в замкнутом хеш-пространстве. Ключ получает первую точку >= его
хеша; после конца выбирается первая. Позиции старых узлов при добавлении нового не меняются.

## 7. Почему переносится не всё?
Новый узел перехватывает только свои дуги. Здесь 3→4 меняет маршрут user 2:
50000 из 100000 строк, то есть 50%. Физический перенос требует отдельного процесса.

## 8. Что такое virtual nodes?
Несколько точек кольца на физический узел. В работе 100 точек на шард.
Обычно они сглаживают размеры дуг и распределяют перенос между несколькими соседями.

## 9. Гарантируется ли идеальная нагрузка?
Нет. Кольцо распределяет ключи, а не QPS/стоимость SQL. Два пользователя не загрузят
равномерно три узла; даже равные строки могут иметь разную популярность.

## 10. Что делать с перегруженным шардом?
Измерять QPS, latency, IO, искать горячие ключи. Кэшировать, ограничивать частоту,
добавлять реплики для чтения; при необходимости выделять/дробить крупного пользователя.
Больше vnode не разделит один горячий ключ. Изменение кольца не заменяет перенос данных.
